# flashcard-extract 开发计划

背景、术语与架构决策见 `_dev/docs/CONTEXT.md`、`_dev/docs/adr/0001-flashcard-extract-environment-agnostic.md`、`_dev/docs/adr/0002-three-stage-flashcard-pipeline.md`。测试记录见 `test-log.md`；本文件只记录已定决策与待办。

## 已定决策

| 决策点 | 结论 |
|---|---|
| 拆卡粒度 | formulation 立场为准：多维对比、完整解释、整体结构卡合法；“最小信息”为默认倾向而非硬规则 |
| 字段命名 | QA 用 `Front:`/`Back:`/`Extra:`，Cloze 用 `Text:`/`Extra:`；formulation 呈现标准与两张认可样例逐字继承 |
| 工作流 | 两模式统一重流程：推荐 3–5 学习目标＋覆盖 → 首批 5–8 → 反馈校准续批 → 覆盖追踪 → 终审后一次写入 |
| 覆盖声明 | 完整覆盖时每批（含修订后与终批）列出实际筛掉的内容（含理由）；无则显式说明“本批覆盖范围内未再筛掉其他有学习价值的内容”；排除项集中列为“已排除” |
| 候选编号 | 保留；聊天展示标“候选 N”，仅用于审阅交流，不写入文件；展示前核对清单项数＝本批候选 Card 数＝声明的本批 Card 数，声明的 Note 数＝本批块数；修订后若重编号，标注新增/修改/合并/未变，合并项注原编号 |
| 成品编号 | 不编号；去重合并不引入编号 |
| 计数口径 | QA 一块为 1 Note＝1 Card；Cloze 一个 `Text:` 块为 1 Note，每个 `{{cN::…}}` 为 1 Card；每批与写入时同时声明 Card 数与 Note 数 |
| Cloze | 纳入，`{{c1::}}` 语法，判据继承；呈现示例待补测/认可 |
| 来源元信息 | 文档制卡附卡级 `Source:` 定位；对话制卡不设（frontmatter topic/date 即出处） |
| Extra 来源依据 | 纳入自检：核心答案与 Extra 的具体事实（枚举、归属、数字、专有名词）均须可追溯；Extra 不得引入素材外具体事实 |
| 术语与改写保真 | 术语与原文所指一致，不得用素材中不存在的第三种说法替换；保留原意强度、范围与可选性（很/相当/几乎/通常/可能/试着/可以/至少/最多/也许/可选/之一等）；素材内部差异保留并标注 |
| Obsidian | 不适配，检测到 vault 时行为与任何环境一致 |
| 对话来源 | 当前会话上下文；对话稿文件按文档制卡处理；不解析 session transcript |
| 落盘路径 | 终审批准后单独确认路径（请求独立成段、置于终批消息末尾，与状态说明分离；用户提前给路径也须复述）；对话 `YYYY-MM-DD-<topic-slug>.md`；文档源同目录 `<source-slug>-cards.md`；slug 用英文 kebab-case |
| 落盘一致性 | 终审后一次写入（暂定），此前各批批准只确定内容；目标文件已存在时先读入、去重合并、展示差异；写入前核对新增/修改卡片＝全部已批准对象（跨批累计）；累计 Card/Note 数声明＝实际写入数 |
| frontmatter | `topic`/`date`；文档制卡加 `source`（相对卡片文件的路径；无法相对时用绝对路径并注明基准） |
| 卡片语言 | 跟随素材语言，专有名词保留原文 |
| 分隔格式 | 单独一行 `---` 分隔卡片；卡片内容禁止单独成行 `---`；成品不设标题或编号 |
| 修订语义 | 批量接受／点名接受或排除／自然语言反馈映射；批准只覆盖已展示对象；不按复习统计自动改卡；合并/收窄须保留旁支事实，舍弃须在修订说明列出 |
| 落盘保真 | 不要求逐字节一致；语义逐字一致，允许引号、空白、分隔线等排版规范化 |
