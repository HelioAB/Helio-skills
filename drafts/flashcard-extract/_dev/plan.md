# flashcard-extract 开发记录

## 定位（2026-10-19 讨论定稿）

- 只做"提炼落盘"：对话 → Q-A-Extra 卡片 Markdown 文件。
- transcript 解析（JSONL 过滤成对话稿）由另一个 skill 负责，本 skill 不碰；仅预留"用户提供对话稿文件"入口。
- Anki 导出由另一个 skill 负责。
- 三段流水线：transcript→对话稿 → 对话稿→卡片（本 skill）→ 卡片→Anki。

## 已定决策

| 决策点 | 结论 |
|---|---|
| 对话来源 | 暂时仅用当前会话上下文；用户给对话稿文件则读入 |
| 落盘位置 | 每次运行时向用户确认路径（建议默认 `YYYY-MM-DD-<topic-slug>.md`） |
| 卡片语言 | 跟随对话语言，专有名词保留原文 |
| 分隔格式 | `---` 分隔卡片 + 文件头 frontmatter（topic/date）；弃用 `## 编号` 标题（无信息量、数量多时视觉疲劳） |

## 关键讨论结论

- compaction 顾虑：把 transcript 导入主会话会挤占上下文、加速压缩，等于搬家家。故 transcript 处理剥离为独立 skill，方向是脚本过滤 + 必要时子代理读取、主会话只收卡片。
- 制卡原则核心：最小信息、自包含（问题必须脱离对话可懂）、Extra 永不放判分必需信息。
- 用户问过的问题天然标记知识缺口，是选卡的主要线索，但问题本身需重写成自包含形式。
