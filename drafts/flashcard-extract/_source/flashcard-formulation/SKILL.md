# 闪卡内容组织

降低从笔记进入间隔复习的门槛。你承担制卡加工，用户选择目标、审阅候选并通过复习反馈迭代；方法适用于不同领域和学习用途，不把首次课程样本固定为通用目标。

首次执行制卡、自检或反馈修订前，读取 [制卡准则与例子](references/formulation.md)。系统权限与对象定义以 vault 的 AGENTS.md 和 SYSTEM_DESIGN.md 为准；Skill 不赋予任何角色启动、写入、移动、外部操作或同步权限。

## 确定目标与覆盖

读取指定材料，结合用户已表达用途，推荐 3～5 个具体的“学习目标＋覆盖范围”，说明包含与略过的内容。用户选择一个并可自由输入；自由输入也可以直接定义目标，不增加组合、改写等操作入口。用户已明确目标时直接沿用，不重复选择；推荐不足时不凑数。

按当批目标决定完整覆盖或选择性覆盖。完整覆盖默认覆盖目标内有学习价值、依据明确的考点，允许筛掉重复信息和偶发操作细节，并说明略过范围；用户明确要求纳入的内容不得擅自排除。允许可查阅、可复制资料保留为工具资产，不默认记忆原文每句话。目标会实质改变制卡方向且缺少必要信息时只问一个关键问题。

## 生成候选

目标明确后直接生成首批约 5～8 个实际回忆任务，不要求人先批准拆解清单。Cloze 说明预计 Card 数；规模按材料适当调整。按反馈校准，再继续后续批次；完整覆盖时持续说明尚未覆盖的范围。

根据回忆任务选择 QA 或 Cloze。QA 用于解释、比较、流程、条件和经验；Cloze 用于在完整语境中回忆关键表达和关系。选型服务于目标，不设置类型配额。

每个实际任务聚焦可判定的目标，保留随机复习所需的领域、对象与条件，避免提示泄漏答案。因果解释可保持完整；整体结构与细节按需要配合。答案按需区分核心与辅助解释，允许同义表达，精确措辞仅在目标要求时使用。

紧密相关的维度可以合在一张 QA 中，题面与答案逐项对应；内容过多或能独立考查时再拆分。除直接概念题外，按目标适量提出有来源依据的情境判断或处理题，不设置情境题数量配额。

重组和改述须能追溯原文，保留适用条件、因果和经验属性；关键歧义或依据缺口只阻断相关候选。原文外知识及推论先提出补充建议，由用户决定是否查证和纳入。

## 自检与呈现

先检查来源忠实度，再检查回忆目标、范围与粒度、随机上下文、答案可判定性、提示泄漏、类型适合度和不必要重复。明显表达问题先改好，不把整份检查过程交给用户承担。

首次生成、反馈修订和最终审阅的所有 QA 候选必须遵守下列标准；Cloze 保留必要结构。仅用户当次明确要求可以调整方法与呈现约定，权限与 Gate 不因此改变。

### QA 内容与呈现标准

- 不为每张卡设置标题或编号；两张卡之间只使用独立一行的 Markdown 横线 `---`，横线前后留空行。
- `Front:`、`Back:`、`Extra:` 及其他字段名不加粗，字段内容从下一行开始。需要展示的来源与归属等元信息也采用字段名与内容分行的形式。
- Front 明确要求回忆的维度或回答范围，并提供必要上下文，不泄漏答案。
- Back 只放判分答案，其中各项均为必答点；接受含义正确的改述，精确术语、数字和顺序仅按目标要求保留。
- 使用简洁完整句，保留必要对象、动作与适用条件，避免需要猜测含义的关键词堆砌。
- Extra 按需补充因果、例子、易错点或适用条件，不重复 Back；没有必要补充时可以省略展示，写入或导出时仍须遵守既有字段要求。
- 只加粗比较维度、核心概念和判分关键词，避免整句加粗。
- 有先后顺序的内容用有序列表，并列特征或对比用无序列表，单一答案用短句；对比对象尽量使用平行句式。
- 命令、路径和标识符用行内代码；只有需要阅读多行代码时才用代码块，并保留必要上下文。
- 来源作为独立审阅元信息，提供页面、标题或可识别段落位置，不混入必答内容；目标是在复习界面中弱化呈现。此约定不新增 Anki 字段，不预先确定来源字段映射、模板或 CSS。

输出前逐项检查以上标准，先自行修正不符合项。没有问题时只展示候选、简短来源及必要注意事项，不附逐卡检查报告、冗长理论说明或质量分数。合格呈现示例见 [制卡准则与例子](references/formulation.md) 的“QA 呈现示例”。

以上是候选审阅格式，不是已验证的插件导出语法；`---` 不代替逐 Note 导出边界。写入或导出时须另核对既有字段、批准边界和真实插件解析；若发生冲突，停止受影响的输出或转换并说明，不静默变换格式或宣称已经兼容。未受影响候选可继续。

## 修订与交付

接收批量接受、点名接受/排除或自然语言反馈。将“太碎”“缺上下文”“答案太多”“不值得记”等反馈转为具体修订；新内容重新展示。批准仅覆盖已展示对象，不自动覆盖下一批。

写入或导出时返回角色契约：展示精确目标和最新差异，确认内容、逐 Note 导出边界与 Gate；不以本 Skill 绕过批准。原始笔记需要更正时展示依据，卡片区外写入交由用户决定并启动相应角色。

复习中的迭代由用户反馈发起；不要根据失败次数或 Anki 统计自动改写、暂停或退役。评估是否减少启动投入、审阅负担是否可接受以及反馈后是否改善；数量不是成功指标。
