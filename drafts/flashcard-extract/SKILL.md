# 从对话或文档提炼闪卡

降低知识进入间隔复习的门槛。你承担制卡加工，用户选择学习目标、审阅候选并以反馈迭代。环境无关：产出是便携 Markdown 卡片文件，任何笔记环境可用。

首次制卡、自检或反馈修订前，读取 [制卡准则与例子](references/criteria.md)。

## 输入

每次调用只处理单一素材，两种模式：

- **对话制卡**：素材是当前会话上下文。只取耐久知识——概念、机制、区别、因果、数字/事实；忽略调试过程、任务协调等过程性内容。用户问过的问题是知识缺口的主要线索，但知识本身可能来自回答的任何部分。对话前后说法有修正时以最后的说法为准，并合并重复。
- **文档制卡**：素材是用户指定的一篇完整 md 文档（知识文档或对话稿），自行读取。

session transcript 解析与 Anki 导出是流水线上其他 skill 的职责，本 skill 不做。

## 确定目标与覆盖

读取素材，结合用户已表达的用途，推荐 3～5 个具体的“学习目标＋覆盖范围”，说明包含与略过的内容。用户选择一个并可自由输入；自由输入也可以直接定义目标，不增加组合、改写等操作入口。用户已明确目标时直接沿用，不重复选择；推荐不足时不凑数。

按当批目标决定完整覆盖或选择性覆盖。完整覆盖默认覆盖目标内有学习价值、依据明确的考点，允许筛掉重复信息和偶发操作细节，并说明略过范围；用户明确要求纳入的内容不得擅自排除。允许可查阅、可复制资料保留为工具资产，不默认记忆原文每句话。目标会实质改变制卡方向且缺少必要信息时只问一个关键问题。

## 生成候选

目标明确后直接生成首批约 5～8 个实际回忆任务，不要求人先批准拆解清单。根据回忆任务选择 QA 或 Cloze；Cloze 说明预计 Card 数。规模按素材适当调整，按反馈校准再继续后续批次；完整覆盖时持续说明尚未覆盖的范围。

每个实际任务聚焦可判定的目标，保留随机复习所需的领域、对象与条件，避免提示泄漏答案。紧密相关的维度可以合在一张 QA 中，题面与答案逐项对应；内容过多或能独立考查时再拆分。重组和改述须能追溯素材原文，保留适用条件、因果和经验属性；关键歧义或依据缺口只阻断相关候选。卡片语言跟随素材语言，专有名词保留原文。

## 自检与呈现

先按 references 的自检判据检查并自行修正，明显表达问题先改好，不把整份检查过程交给用户承担。

展示完整候选（呈现标准见 references），每个候选都带编号，并附每张一行“编号＋问题”的清单；展示前核对清单项数＝本批候选张数＝消息声明的本批张数。编号仅用于审阅交流，不写入文件。修订后重新展示时，若重新编号，逐项标注新增、修改、合并或未变，合并项注明原编号。文档制卡的每个候选附来源定位（标题路径或可识别段落位置）；对话制卡不加卡级来源，卡片文件的 frontmatter 已承担出处。

## 修订与批准

接收批量接受、点名接受/排除或自然语言反馈；将“太碎”“缺上下文”“答案太多”“不值得记”等反馈转为具体修订（映射见 references），新内容重新展示。批准仅覆盖已展示对象，不自动覆盖下一批。素材原文需要更正时展示依据，由用户决定并另行处理，不代改原文。复习阶段的修订同样由用户反馈发起，不根据失败次数或统计自动改写、暂停或退役卡片。

## 落盘

全部已展示批次获批准后，与用户确认输出路径再写入：对话制卡建议 `YYYY-MM-DD-<topic-slug>.md`；文档制卡建议源文档同目录 `<source-slug>-cards.md`；slug 用英文 kebab-case。

路径确认请求单独成段，置于终批消息末尾，与“展示完毕”“frontmatter 说明”等状态说明分开，不与其他内容混排；确认方式不限，不绑定特定提问工具。

写入前核对：本次新增或修改的卡片＝已批准对象，消息中的累计张数声明＝实际写入张数。目标文件已存在时先读入已有卡，去重合并，展示差异并经确认后写入。

文件格式：

- frontmatter：`topic`、`date`；文档制卡另加 `source`（相对卡片文件的路径；无法相对时用绝对路径并注明基准）。
- QA 卡用 `Front:` / `Back:` / 可选 `Extra:`；文档制卡另加 `Source:`。字段名不加粗，内容从下一行开始。
- Cloze 卡用 `Text:`（内含 `{{c1::…}}` 删除段）加可选 `Extra:`。
- 卡片之间用单独一行 `---` 分隔，横线前后留空行；卡片内容中禁止出现单独成行的 `---`（改写为破折号或列表）。
