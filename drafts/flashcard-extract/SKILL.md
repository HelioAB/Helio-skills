# 从对话提炼闪卡

把当前会话中的耐久知识提炼成 Q-A-Extra 卡片并落盘，供导出类 skill（如 Anki）后续使用。

## 流程

1. **识别知识**：扫描对话，只取耐久知识——概念、机制、区别、因果、数字/事实。忽略过程性内容（调试过程、任务协调、文件操作、寒暄）。用户问过的问题是主要线索——它们标记了知识缺口——但知识本身可能来自回答的任何部分。
2. **核实**：对话前后说法有修正时，以最后的说法为准；合并重复。
3. **制卡**：按下方原则改写。一个长回答通常拆成多张卡。
4. **过目并落盘**：向用户展示卡片清单（每张一行：编号 + 问题），同时确认输出路径与文件名（可建议 `YYYY-MM-DD-<topic-slug>.md`）。用户删改确认后写入文件。

提炼来源：默认当前会话上下文；若用户提供了现成对话稿文件则读入。不要解析 session transcript——那是其他 skill 的职责。

## 制卡原则

- **最小信息**：一张卡只考一件事；长答案必须拆。
- **自包含**：问题重写为脱离对话也能读懂；消灭"它 / 这个 / 刚才那个"式指代。
- 问题有唯一确定答案；避免是非题。
- 答案压缩到本质；重要细节拆成独立卡片。
- **Extra 只放**提示、助记、边界情况；永不放判断答案对错所必需的信息；可省略。
- 语言跟随对话语言，专有名词保留原文。

## 文件格式

````markdown
---
topic: tls-basics
date: 2026-10-19
---

Q: TLS 证书里放的是公钥还是私钥？
A: 公钥。私钥只保存在服务器端，从不传输。
Extra: 服务器用私钥签名证明持有证书，客户端用证书内的公钥验证。

---

Q: …
A: …
````

- 文件头 frontmatter 只放 `topic`、`date`。
- 每张卡以 `Q:` / `A:` / `Extra:` 标签起始，标签后可续行；卡片之间用单独一行 `---` 分隔。
- `---` 前必须空行；卡片内容中禁止出现单独成行的 `---`（改写为破折号或列表）。
